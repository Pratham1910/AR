# 3D (Phase 4)

## Backend

- **`Model3D`** (`backend/app/models/model3d.py`) points an Asset (and
  optionally one Component) at a GLB/glTF file. It is intentionally thin —
  the scene graph lives inside the GLB itself; this row only carries the
  digital-thread identifiers (Project.md #38).
- **`Component.cad_node_id`** links a Component row to a named node inside
  that GLB's scene graph (Project.md #20's `cadNodeId`), so
  `target.componentId` in a procedure step can eventually resolve to "the
  mesh named X in the 3D model" without hard-coding mesh names anywhere else.
- GLB files are served statically at `/static/models/<storage_key>`
  (`app/main.py` mounts `MODELS_3D_DIR`, default `data/models/`) rather than
  stored as DB blobs (Project.md #65/#66's storage rule extended to 3D
  assets). `GET /api/models3d?asset_id=...` / `POST /api/models3d` manage the
  pointer rows.
- **`POST /api/models3d/upload`** (multipart: `asset_id`, `name`, `file`,
  optional `component_id`/`real_world_height_m`): saves the uploaded `.glb`
  under `models_3d_dir`, and — if `real_world_height_m` is given — computes
  `scale` automatically from the file's own mesh bounds
  (`app/services/model3d/glb_inspect.py`) instead of leaving it at the
  default `1.0`. This is the exact correction `bottle.glb` needed by hand
  (Project.md's provided placeholder was an unscaled ~5.3m-tall Blender
  export) — automated here by reading the glTF JSON chunk's POSITION
  accessor `min`/`max` directly (no full mesh parser needed) rather than
  requiring another manual inspection for every new model.

## Frontend — `frontend/src/features/viewer3d/ThreeViewer.tsx`

Plain Three.js (not react-three-fiber) — deliberately, so the same
scene-setup pattern carries into the Phase 5 AR overlay, which needs direct
control over camera/object matrices from OpenCV pose output rather than a
declarative wrapper. Supports load, orbit/zoom/pan (via `OrbitControls`), and
auto-frames the camera on the loaded model's bounding box. Also lists every
node name in the loaded scene, so you can confirm what a `cad_node_id` should
be set to.

## Demo data

`python -m app.workers.seed_demo` registers `BOTTLE-001` (asset) /
`BOTTLE-BODY-001` (component, `cad_node_id="Cylinder"`) / a `Model3D` row
pointing at `data/models/bottle.glb` — the file you provided
(`3D-models/TEST BOTTLEglb.glb`), copied in as the Phase 4/5 test asset. It's
a single-mesh placeholder (no sub-parts), so it proves the load/view/register
pipeline but isn't a multi-step disassembly demo like `PUMP-001`.

Test it: run the app, open the **3D / AR Registration** tab, pick
`BOTTLE-001`, click **3D Viewer**.

## Adding more models

`frontend/src/features/viewer3d/UploadModelForm.tsx` (the "+ Upload 3D
model" button on the 3D / AR Registration page): pick an existing asset or
name a new one, choose a `.glb` file, and give its real-world height in
meters if you know it — that's the whole flow, no hand-written API calls or
manual GLB inspection needed. Only `.glb` (binary glTF) is supported, not
plain-JSON `.gltf`.
